## 1. 背景与目标

短视频创作者在写脚本时有三类高频问题：产品卖点记不全、写出来没有事实依据；成片时长不可控，反复返工；品牌与平台规则靠人肉记忆，容易踩线。本项目做一个面向短视频创作者的脚本助手（先内部试用），创作者给主题、受众、平台、目标时长、风格，Agent 自主检索产品素材、生成分镜脚本、估算时长、检查品牌与平台规则，产出**有事实依据、能卡住时长、可直接编辑**的脚本。

### 1.1 可度量的目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 事实可追溯 | 脚本中每一条产品事实/卖点/参数都能指回素材 ID 与原文片段；自动检查对"数字、百分比、资质背书、绝对化表述"逐条比对引用，缺失即判 error |
| G2 | 时长可控 | 最终 `<预计总时长>` 落在目标时长的允许区间内；若修正后仍不可满足，返回 `failed` 并给出证据，不得虚报 |
| G3 | 规则真实执行 | 品牌禁用词、平台规范、夸大表述三组规则每次运行都真实检查；违规项可定位到分镜与命中文本 |
| G4 | 过程可观测 | 每一步落盘 trace：动作、参数、观察摘要；不记录模型内部思维过程 |
| G5 | 验收场景可复现 | 五个验收场景 + 状态覆盖场景均可按固定命令复跑，产出输入、输出、trace、结论 |

### 1.2 成功的定义（第一版）

内部试用者能用一条命令，在真实 DeepSeek 模型下跑通五个验收场景；参考实例（P01、30 秒、38→28）可作为正式用例确定性复跑；受控对照（只改目标时长/检索结果）能拿出两条实际 trace 证明动作随之改变；产出物可直接复制进剪辑流程继续改；所有硬约束在 `examples/` 下有实际运行证据。离线模式可让自动化测试在没有密钥/网络时稳定复跑全流程，但**离线模式只证明流程，不证明模型决策质量**。

## 2. 用户与使用场景

### 2.1 用户

| 角色 | 描述 | 诉求 |
| --- | --- | --- |
| 短视频创作者（主用户） | 独立创作者/小团队编导，日常产出 15–180 秒短视频 | 快速拿到有事实依据、时长达标、规则合规的可编辑脚本 |
| 需求方（兼评审） | 项目发起人，内部试用后自己也会用 | 能判定每条硬约束是否真的被执行，能复跑验收场景 |
| 开发方 | 维护代码、数据、文档与证据 | 契约清晰、可测试、可维护 |

本版本不面向外部客户、不做账号体系，不承诺多用户并发。

### 2.2 典型场景

1. **日常生成**：给"新功能字幕上线 / 剪辑新手 / 抖音 / 30 秒 / 轻快教程"，拿到 4–6 个分镜、总时长落在 27–33 秒、带 P01 素材引用的脚本。
2. **素材不足**：给了一个素材库里没有的主题，Agent 先改写检索词再试，仍无结果时向用户要补充信息（`needs_input`），而不是编一条卖点。
3. **规则风险**：脚本初稿出现平台禁用词或夸大表述，规则检查命中后修正，再检查通过；修正不了则明确失败。
4. **时长返工**：初稿 38 秒、目标 30 秒，估算发现超限，压缩旁白/字幕或减少分镜后重估为 28 秒，输出新稿。
5. **工具故障复盘**：注入检索超时，观察 Agent 是否重试/换方案，以及 trace 是否如实记录失败。
6. **评审复盘**：需求方按 `examples/` 下固定命令复跑，对照输出与 trace 判定。
7. **受控对照**：同一主题只改目标时长（30s/60s）或只改检索结果（有素材/无素材），对照两条 trace 证明 Agent 的下一步动作确实随输入变化。

## 3. 范围

### 3.1 本版本做

- 统一 CLI 入口（参数或输入 JSON，无交互式输入），真实 / 离线两种模式一键切换。
- 三个本地业务工具：素材检索、时长估算、规则检查（合成数据，确定性实现）。
- 显式 LangGraph `StateGraph` 编排：模型节点、工具节点、收尾校验节点，逐步骤 trace。
- 结构化输出：标题、分镜列表（画面、旁白/字幕、时长）、预计总时长、素材引用、风险、任务状态。
- 动态决策：检索无结果改写/请求补充；时长或规则不过改稿重查；工具失败调整或明确失败；步数/工具调用上限强制。
- 工具失败注入（命令行或输入 JSON），用于可复现演示。
- 五类验收场景 + 核心参考实例（P01 30 秒 38→28）+ 受控对照（只改目标时长/检索结果）的证据材料（输入、输出、trace、复跑命令、测试结果）。

### 3.2 本版本不做

- Web UI、HTTP API、数据库、Docker、部署、鉴权、账号体系。
- 多 Agent / 多轮会话 / 长期记忆 / checkpointer 持久化。
- 外部 RAG、爬虫、真实素材库接入、向量检索、在线搜索。
- 视频生成、剪辑、发布、平台 API 对接；仅产出可编辑文本脚本。
- 真实品牌/平台规则的法务级校验（规则集为合成近似数据，见 §9.2）。
- 多语言脚本（输出语言为中文）；非中文平台的本地化适配。
- 计费、监控告警、并发与限流（单进程单次运行）。

### 3.3 边界与约束

- 单次运行只产出一个脚本；同一输入重复运行可得到不同文本（真实模型非确定），但结构、约束判定必须一致。
- 全部素材、规则为合成虚构数据，与任何真实产品、平台条款无关；禁止引入真实品牌数据。
- 仅支持 Windows + Python 3.13.5 + 项目内 `.venv`；所有文件 UTF-8 显式读写；Windows 命令先 `PYTHONUTF8=1`。
- `.env.local` 存真实密钥，禁止提交、打印、复制进任何文件/日志/trace；`.env.example` 只放占位符。

## 4. 输入与输出（契约摘要）

详细的 JSON Schema、状态机、trace 字段见 `docs/02-solution.md` §4/§5/§10；本节只定义需求侧契约。

### 4.1 输入

| 字段 | 必需 | 类型/约束 | 说明 |
| --- | --- | --- | --- |
| `topic` | 是 | 非空字符串，≤100 字 | 脚本主题 |
| `audience` | 是 | 非空字符串，≤100 字 | 目标受众 |
| `platform` | 是 | 枚举：`douyin` / `kuaishou` / `xiaohongshu` / `shipinhao`（见 §11 Q2，已定稿） | 发布平台，决定平台规则集 |
| `target_duration_s` | 是 | 整数，5–300，单位秒 | 目标时长 |
| `style` | 是 | 非空字符串，≤50 字 | 风格（如"轻快教程""生活感口播"） |
| `extra_notes` | 否 | 字符串，≤500 字 | 补充信息 |
| `failure_injection` | 否 | 列表，见 `02` §12 | 仅用于演示/测试的工具失败注入 |

来源优先级：CLI 参数 > 输入 JSON > 默认值（无必填默认值）。输入可整体用 `--input <json>` 传入，也可用 CLI 参数；两者同时给出时 CLI 参数覆盖同名字段。**任何缺失/非法必填字段都不得交给模型猜测**。

### 4.2 输出

一次运行输出一份 JSON（stdout + 文件），必须包含：

- `status`：`completed` / `needs_input` / `incomplete` / `failed`；
- 脚本（`script`，除 `needs_input` 外尽量给出）：标题、分镜列表（每镜画面描述、旁白/字幕、时长）、预计总时长、素材引用（素材 ID + 原文片段）；
- `checks`：最终时长检查与规则检查结果；
- `risks`：残余风险（warning 级违规、工具错误历史、校验口径提示等）；
- `needs_input`（当 `needs_input`）或 `failure`（当 `failed`/`incomplete`）的明确原因与证据；
- `tool_errors`、`budget`、`trace_path`、`mode`、`run_id`、`generated_at`。

### 4.3 状态与退出码

| 状态 | 含义 | 进程退出码 |
| --- | --- | --- |
| `completed` | 脚本已提交且最终硬校验全部通过 | 0 |
| `needs_input` | 关键信息缺失/平台不支持，或检索无结果且模型请求补充 | 3 |
| `incomplete` | 达到步数或工具调用上限仍未收尾 | 4 |
| `failed` | 明确失败：约束无法同时满足、工具持续失败、模型提前终止且校验不过等 | 5 |
| —— | 内部错误（配置缺失、数据集不可用、未捕获异常） | 1 |
| —— | 模型调用失败（LLMError：网络/协议/截断）：业务 `failed`，仍有 output/trace | 5 |
| —— | CLI 用法错误 / 输入 JSON 解析失败 | 2 |

`needs_input` / `incomplete` / `failed` 都是**正常业务结果**，必须输出 JSON 与 trace；只有内部错误与用法错误走 stderr 且不承诺完整输出。模型调用失败（LLMError）归入 `failed`/退出码 5；配置缺失、数据集不可用、未捕获异常才归入内部错误/退出码 1。

## 5. 功能需求

| 编号 | 需求 | 需求要点 |
| --- | --- | --- |
| FR-1 | 输入校验 | 环境可用前提下，必填缺失/类型非法/时长越界/平台不支持 → `needs_input`（配置缺失/数据集不可用属于内部错误退出 1），列出缺失字段；不调用模型、不编造 |
| FR-2 | 素材检索 | 按关键词/主题返回素材 ID、标题、事实片段（fact_id + 原文）；结果确定性排序；无结果返回空列表，不报假成功 |
| FR-3 | 脚本生成 | 通过原生 tool calling 提交结构化脚本；每条产品事实/卖点必须带素材 ID + 原文引用；不得写素材外的事实、效果数据、认证 |
| FR-4 | 时长估算与修正 | 对分镜脚本做确定性估算，返回每镜时长与总时长及是否在允许区间；超限必须改稿重估，仍不满足则明确失败 |
| FR-5 | 规则检查 | 品牌禁用词、平台规范、夸大表述真实检查；违规项含规则 ID、位置、命中文本、修改建议；有 error 不得判成功 |
| FR-6 | 引用校验 | 引用必须指向真实素材/事实，`quote` 必须与素材原文逐字匹配；数字/百分比/资质类表述必须有引用支撑 |
| FR-7 | 动态决策 | 检索无结果时由模型决定改写查询或请求补充；时长/规则不过时改稿重查；工具失败时调整动作或明确失败；不得静默编造 |
| FR-8 | 状态与预算 | 四状态明确；步数上限默认 8、工具调用上限由编排层强制（批前预检，超限批不执行并记录未执行调用）；**触顶且未 finish → `incomplete`；最后一个允许步 finish 且复算通过 → `completed`**；保留未完成证据 |
| FR-9 | trace | 每步落盘：步骤序号、动作（工具名+参数）、观察摘要；`decision_note` 记录模型可见 content 中的 ≤40 字说明并标来源 `model`/`missing`；另由编排层生成 `decision_summary`（只拼接上一步实际观察摘要与本步实际工具名/关键参数，标 `source=orchestrator`，不推断模型动机）；不记录 `reasoning_content`/内部思维 |
| FR-10 | 失败注入 | CLI 或输入 JSON 指定工具、错误类型、第几次调用失败；同一输入可复现同一失败点 |
| FR-11 | 双模式 | 真实模式读 `.env.local` 调 DeepSeek；离线模式用固定策略 mock 跑通全流程；二者同一 LLM 接口、同一图、同一工具 |
| FR-12 | CLI | `python -m src.cli run ...` 非交互；输入 JSON 与参数两种方式；输出 JSON 到 stdout 并落盘；命令写入 README |
| FR-13 | 证据 | `examples/` 每组用例含输入、实际输出、trace、复跑命令；trace 来自实际运行；文档引用具体文件 |
| FR-14 | 受控对照 | 同一主题只改一个变量（目标时长 30/60，或检索结果有/无素材）跑两组，留存两条实际 trace 与对比表，证明下一步动作随输入改变；trace 来源与离线标注符合证据规范 |

## 6. 业务硬约束（红线）

| 编号 | 约束 | 违反判定 |
| --- | --- | --- |
| R1 | 事实可追溯：脚本中每条产品事实、卖点、参数必须引用素材库素材 ID 与原文片段 | 引用不存在/不逐字匹配/数字或资质表述无引用 → 规则检查 error；最终 `completed` 要求无 error |
| R2 | 禁止编造：素材没有的事实、效果数据、认证不得写入 | 自动检查 + 人工评审；典型反例：素材 P01 只有"支持字幕"，脚本写"效率提升 80%"属严重缺陷 |
| R3 | 时长真实计算：预计总时长必须由确定性估算工具算出并落在允许区间；模型不得自行填时长 | 输出分镜时长与公式复算不一致、总时长不等于分镜之和 → 测试直接失败 |
| R4 | 规则真实执行：每次运行必须实际调用规则检查；命中后修正或标为风险 | trace 无规则检查调用、或 error 违规仍判 `completed` → 验收失败 |
| R5 | 检索无结果不得静默编造 | 无结果后脚本出现素材外事实 → 严重缺陷 |
| R6 | 工具失败不得掩盖 | 工具错误必须出现在 trace 与输出 `tool_errors`；不得以假结果替代 |
| R7 | 输出可编辑、结构化 | 缺标题/分镜/时长/引用/风险/状态任一字段 → 验收失败 |
| R8 | 状态真实 | 只有硬校验全部通过才可 `completed`；模型自称完成不算数 |
| R9 | 密钥安全 | `.env.local` 不入库、不打印、不进 trace/输出/证据；`.env.example` 无真实值 |

## 7. 验收场景

所有场景需能在真实模式与离线模式分别复跑；离线结果用于自动化判定流程，真实模式结果用于证明模型决策质量。复跑命令、输入、输出、trace 统一放在 `examples/<场景目录>/`（均已落盘并纳入证据一致性测试）。判定条件以最终 `output.json` 与 `trace.jsonl` 为准。**证据来源硬性要求：`examples/` 下所有 trace 必须由本仓库 CLI 实际运行生成（真实模型，或 `--offline` 且明确标注 mode），禁止手写、补写、拼接或人工修改；重跑时整文件覆盖。**

### AC-01 正常生成

- **输入**：`topic=字幕功能上线`（或等价主题）、`audience=剪辑新手`、`platform=douyin`、`target_duration_s=30`、`style=轻快教程`；素材库中 P01 可用。
- **判定条件（全部成立）**：
  1. 退出码 0，`status == "completed"`；
  2. `script` 非空，分镜数 ≥ 3，每镜含非空 `visual` 与 `narration`/`caption` 至少一项；
  3. 每镜 `duration_s` 与时长公式复算一致（整数秒），`estimated_total_duration_s == sum(duration_s)`，且落在 `[27, 33]`；
  4. 引用非空，每条 `quote` 可在对应素材事实原文中逐字找到；
  5. 最终规则检查 `ok == true`（0 个 error）；
  6. trace 至少包含：素材检索、提交脚本、时长估算、规则检查、finish 五类动作，且顺序符合"先检索后写稿"；
  7. 输出 `tool_errors == []`（未注入失败时）。

### AC-02 缺关键信息

- **输入**：缺少 `audience`（且不提供默认值）。
- **判定条件**：
  1. 退出码 3，`status == "needs_input"`；
  2. `needs_input.missing_fields` 明确包含 `audience`，并给出向用户提问的 `question`；
  3. 不产生脚本、不产生引用；
  4. trace 中无 `model_response` 事件（未把缺信息交给模型猜），有输入校验事件与收尾事件。

### AC-03 素材检索无结果

- **AC-03a（持续无结果 → 请求补充）**：`topic` 选择素材库明确没有覆盖的主题（如"火星旅拍攻略"）。
  - 判定：`status == "needs_input"`；trace 中检索调用 ≥ 2 次且查询词不同，每次 `total == 0`；输出无脚本/无引用；不得出现任何素材外产品事实。
- **AC-03b（改写后命中 → 完成）**：`topic` 使用模糊说法（如"怎么加字幕"），检索词改写后命中 P01。
  - 判定：`status == "completed"`；trace 中至少有两次查询词不同的检索，第一次可为空/不足，最终命中的素材 ID 出现在脚本引用中；不得编造未命中素材的事实。
- 真实模型可能把 AC-03a 改写为可命中的查询，此时按 AC-03b 判定；但若最终 `needs_input`，必须满足 AC-03a 的 trace 条件。

### AC-04 工具失败

- **AC-04a（可恢复失败）**：注入 `search_materials` 第 1 次调用 `timeout`。
  - 判定：`tool_errors` 含该注入错误（`injected == true`）；trace 中该工具先失败后成功；最终 `status` 为 `completed`（若其余约束满足），脚本引用真实素材；不得用失败结果编造。
- **AC-04b（持续失败 → 明确失败）**：注入 `search_materials` 所有调用 `unavailable`。
  - 判定：`status == "failed"`（若步数先触顶则允许 `incomplete`，二者均判为"未假装成功"）；`tool_errors` 非空且与 trace 一致；输出无编造素材引用；`failure`/未完成原因引用工具错误。
- 两次注入都必须可通过同一命令复跑得到相同失败点。

### AC-05 超时长修正（参考实例，核心证据）

- **输入**：素材 P01 只有一条事实"支持字幕"；`topic=字幕功能上线`、`audience=剪辑新手`、`platform=douyin`、`target_duration_s=30`、`style=轻快教程`；检索命中 P01。
- **正式可复跑用例（离线确定性，核心证据，`examples/05_over_duration/offline/`）**：
  1. 首次时长估算 `estimated_total_duration_s == 38`（>30），`within == false`、`verdict == "too_long"`；
  2. Agent 依据检查结果修改脚本（提交稿变化：旁白/字幕字数减少或分镜减少，trace 中两次 `submit_script` 参数可对比），并**重新估算**；
  3. 最终 `status == "completed"`，`estimated_total_duration_s == 28`（≤30 且落在 `[27, 33]`）；
  4. 输出含分镜、P01 引用（`material_id=P01`、`quote="支持字幕"`）与预计总时长；引用仅来自 P01 原文，不得出现"效率提升 80%"等素材外数据（规则检查无 error）；
  5. 分镜时长与总时长由公式逐镜复算一致，无模型自填时长；
  6. 该用例必须由固定命令复跑得到同样数值，trace 标注 `mode=offline`。
- **真实模型同场景（`examples/05_over_duration/real/`，加分证据，不作唯一依赖）**：同一输入真实跑一次，如实记录首稿与最终估算值。运行时判定只用通用区间：最终落在 27–33 且引用可回溯 → `completed`（≤30 记"与参考实例一致"，31–33 记"在容差内、高于参考实例"）；未落入区间按实际状态记录。压缩分支是否触发、是否恰好 38→28 均如实记录，不得为凑参考数值改写 trace 或强行判 `failed`。
- **正式真实模式决策证据不依赖本场景**，见 §7.2：使用刺激必然发生的三条场景（AC-03a、AC-08b no_hit、AC-04a）。

### AC-06 无法满足（明确失败）

- **输入**：`platform=kuaishou`、`target_duration_s=30`；合成规则集中该渠道内部试用规范 `max_total_duration_s=25`（规则 ID `PLAT-kuaishou-DUR-001`）。目标区间 `[27, 33]` 与上限 25 互斥。
- **判定条件**：
  1. `status == "failed"`（不得 `completed`/`incomplete`），退出码 5；
  2. trace 中至少一次时长估算 `too_long`，且至少一次规则检查命中 `PLAT-kuaishou-DUR-001` 平台时长违规，证明 Agent 尝试过；
  3. `failure.code` 为明确原因（`cannot_satisfy` / `constraints_conflict`），`failure.evidence` 能同时看到"目标区间下限 27"与"平台上限 25"的冲突证据；
  4. 不得输出通过校验的 `completed` 结论；`script` 如保留仅为证据稿。

### AC-07 步数上限（状态覆盖）

- **输入**：正常场景 + `--max-steps 3`（或等价的低预算配置），模型在预算内未能收尾。
- **判定条件**：
  1. `status == "incomplete"`，退出码 4；
  2. `budget.steps_used == 3`（或配置值），且 trace 最后为收尾事件、写明触顶原因；
  3. 不把未通过校验的草稿判为 `completed`；输出如有 `script` 必须附带未解决的检查结论。
- **边界口径**：若模型恰在最后一个允许步 `finish` 且 finalize 复算通过，必须判 `completed`（不得因为"触顶"判 `incomplete`）；此边界由独立测试覆盖（02 §15.2）。

### AC-08 受控对照（只改一个输入变量，动作随之改变）

目的：证明"改目标时长或换检索结果时，模型的下一步动作跟着变"，排除主题/受众/平台/风格等混杂变量。两组输入除被研究的变量外逐字段相同；每条 trace 必须来自实际运行并标注 mode。

- **AC-08a 只改目标时长（30s vs 60s）**：`examples/08_controlled_target/{target_30,target_60}/`。
  - 离线确定性判定：两组首稿同为 38 秒；30s 组判 `too_long` → 压缩到 28 秒（≤30），60s 组判 `too_short` → 扩张到 58 秒（落在 `[54,66]`）；两条 trace 的估算结论、改稿方向、分镜数不同。
  - 真实模型判定（加分证据，不作唯一依赖）：只断言两组各自落在通用区间、引用可回溯、状态真实；实际首稿/最终估算、改稿次数、分镜数、动作差异如实填表，**不硬性要求压缩/扩张方向差异**；某组一次成稿如实标注，不得补写。
- **AC-08b 只改检索结果（有素材 vs 无素材）**：`examples/09_controlled_retrieval/{hit,no_hit}/`；两组输入完全相同，仅数据集不同：`hit` 用默认 `data/`，`no_hit` 用 `--data-dir examples/09_controlled_retrieval/no_hit_data/`（合成素材为空、品牌/平台规则同一套）。
  - 离线确定性判定：`hit` → 检索命中 → 提交/估算/规则 → `completed` 且引用 P01；`no_hit` → 至少 2 次检索均为 0 条 → `ask_user` → `needs_input`；两条 trace 的查询词、结果数与动作序列不同。
  - 真实模型判定：`hit` → `completed` 且引用 P01（硬约束同 AC-01）；`no_hit` → 与 AC-03a 一致，首选 `needs_input`；若实际返回 `failed`，保留真实结果并在 README 标注为分支偏差（同时说明未编造素材事实），由评审决定是否需要重跑，不得补写。
- 两组对照的对比结论（实际数字 + 具体 trace 事件）写入各目录 README；离线对照为可判定的确定性证据；真实对照中 `AC-08b no_hit` 属正式决策证据（§7.2），`AC-08a` 真实对照为加分证据，二者必须分开标注。

### 7.2 正式真实模式"决策证据"（三条刺激必然发生的场景）

真实模型对同一刺激可能有多种合理反应（压缩/不压缩、一次成稿/多次改稿），因此**正式真实证据不以"某个特定动作是否恰好发生"为前提**。固定以下三条刺激必然发生的场景，README 与 `docs/03` 标注为"决策证据"；**AC-05 real 与 AC-08a real 只作加分证据**。

| 编号 | 场景 | 必然发生的刺激 | 真实模式判定 |
| --- | --- | --- | --- |
| AC-03a | "火星旅拍攻略"（素材库无覆盖） | 检索连续 0 结果 | 观察到改写查询，并最终 `ask_user` → `needs_input`（验收口径）；或明确失败且说明"检索持续无结果"，如实记录为分支偏差；全程不得编造素材事实 |
| AC-08b no_hit | 同主题、空素材数据集（`--data-dir` 变体） | 检索连续 0 结果 | 与 hit 组 trace 对照：查询词、`total_matched`、动作序列不同；状态判定同上 |
| AC-04a | 注入 `search_materials=timeout@1` | 第 1 次检索必然失败 | 观察到"失败→重试/调整"，`tool_errors` 记录注入错误；最终不把失败当成功；与无注入 trace 对照动作不同 |

- 三条均不依赖模型是否恰好把时长压到 28 秒，可稳定作为"下一步动作随观察结果改变"的真实证据。
- 判定以 trace 中可观察的 `tool_calls`、查询词/参数、`total_matched`、状态为准，不做文案比对。
- 真实运行与离线运行分别保存、分别标注；离线固定策略 trace 不能替代真实 trace。

## 9. 术语与数据约定

### 9.1 术语

| 术语 | 定义 |
| --- | --- |
| 素材（Material） | 合成的产品资料条目，含素材 ID、标题、标签、若干条事实 |
| 事实（Fact） | 素材中的一条最小可引用陈述，如"支持字幕"，有 fact_id 与原文 |
| 事实片段（quote） | 从事实原文中逐字截取的引用文本，用于脚本引用与校验 |
| 引用（Citation） | `{material_id, fact_id, quote}` 三元组，附着在分镜上，支撑该镜的产品表述 |
| 分镜（Shot） | 脚本最小单元：画面描述、旁白、字幕、计算时长、引用列表 |
| 目标时长 / 允许区间 | 输入的 `target_duration_s` 与由容差公式算出的 `[min_s, max_s]`（见 02 §7） |
| 估算（Estimate） | 时长工具对脚本的确定性计算，输出逐镜时长、总时长、是否在区间 |
| 违规项（Violation） | 规则检查命中结果：规则 ID、类别、严重级、位置、命中文本、建议 |
| 风险（Risk） | 最终输出中的残余风险：warning 违规、工具错误历史、校验限制说明等；`completed` 时不得含 error |
| 步（Step） | 一次模型调用；默认上限 8 |
| 工具调用（Tool call） | 模型发起的一次工具动作；默认上限 `2 × max_steps` |
| trace | 运行过程的事件流（JSONL），用于复盘与验收 |
| 注入（Injection） | 人为让指定工具在指定调用次数上失败，用于演示与测试 |
| 真实模式 / 离线模式 | 调 DeepSeek / 用固定策略 mock；两者共用同一图和工具 |
| run_id | 单次运行唯一标识，形如 `20261028T221500+0800-7f3a9c` |

### 9.2 数据约定

- **全部合成**：`data/materials.json`、`data/brand_rules.json`、`data/platform_rules.json` 为合成虚构数据，禁止真实品牌/平台条款；P01 固定只含一条事实"支持字幕"（验收参考实例）。
- **ID 约定**：素材 `P01`、`P02`…；事实 `<素材ID>-F<序号>`（如 `P01-F1`）；规则 `BRAND-###`（品牌禁用词）、`PLAT-<platform>-###`（平台规范）、`EXAG-###`（夸大表述）、`CITE-###`（引用/事实支撑）、`STRUCT-###`（结构告警）。分镜序号从 1 开始。
- **时长与字数**：时长一律整数秒；字数按"删除空白字符后计数，标点计入"；公式与常量见 02 §7，写死在代码常量并标注 `formula_version`。
- **JSON**：UTF-8 无 BOM；输出文件 2 空格缩进；trace 为 JSONL（一行一事件）；字段名英文 snake_case。
- **时间**：ISO-8601 带时区（如 `2026-10-28T22:15:00+08:00`）。
- **状态枚举**：仅 `completed` / `needs_input` / `incomplete` / `failed` 四值。
- **输出文件**：默认写 `runs/<run_id>/output.json` 与 `runs/<run_id>/trace.jsonl`（`runs/` 已 gitignore）；验收证据复制到 `examples/` 并提交。
- **数据版本**：运行开始时对三个数据文件计算 sha256 前 12 位作为 `data_digest`，写入 trace 与输出，保证"检索结果变了，动作也跟着变"可追溯。
- **证据来源**：`examples/` 下所有 trace 只能是 CLI 实际运行产物（真实模型或 `--offline`，由文件名后缀、`run_start.mode` 与目录 README 三处一致标注）；禁止手写/补写/编辑/跨运行拼接；实测结果与预期分支不符时保留真实结果并说明，不得为凑验收条件重写证据。
- **安全**：`.env.local` 仅真实模式读取；`LLM_API_KEY` 不进入 state、trace、输出、错误消息；trace 写出前对密钥值做 `***` 替换。

## 10. 假设

1. **容差**：时长时间允许区间暂定 `ceil(0.9×目标)` 至 `floor(1.1×目标)`（30 秒 → 27–33 秒），按需求方拍板可调；调整只改一处常量并同步文档与测试。**真实模式运行时只用该通用区间**；AC-05 的 38→28 是离线参考实例的核心证据，真实模式落在 27–33 即 `completed`（≤30 记与参考一致，31–33 记容差内高于参考），不因未压到 ≤30 判失败。
2. **平台**：首发支持抖音、快手、小红书、视频号四个平台，规则集为合成近似；未知平台按 `needs_input` 处理。其中快手渠道内部试用上限合成设为 25 秒，专门用于 AC-06 的时长冲突场景，不代表真实平台规则。
3. **引用粒度**：引用挂在分镜级（一个分镜可有多条引用），校验采用"素材/事实存在 + 原文逐字匹配 + 数字/资质/绝对化表述必须有引用支撑"的判定口径；语义级事实核查依赖模型自约束与人工评审，自动检查不承诺语义等价判断。
4. **单次运行**：模型只处理一次请求，不跨运行记忆；多次改稿在本次运行内完成。
5. **真实模型行为不可完全确定**：验收对真实模式的判定基于约束（状态、时长区间、引用有效、规则 error 为 0），不要求固定文本；离线模式使用固定策略保证数值可复现（38→28）；真实模型若未触发某分支，如实标注"分支未触发"，不得补写 trace。
